# Database Migration Documentation

## BookStoreDB — Chuyển đổi từ SQL Server sang PostgreSQL

Tài liệu này ghi lại toàn bộ quá trình chuyển đổi hệ quản trị cơ sở dữ liệu của project BookStoreDB, từ SQL Server sang PostgreSQL, bao gồm các khác biệt cú pháp, lỗi phát sinh, cách sửa, kiểm tra schema, dữ liệu và ứng dụng.

## 1. Tổng quan

| Hạng mục | Giá trị |
|---|---|
| Project | BookStoreDB |
| Database nguồn | Microsoft SQL Server |
| Database đích | PostgreSQL |
| Công cụ | DBeaver |
| Script đích | `BookStoreDB_PostgreSQL_Corrected.sql` |
| Trạng thái | Đã chuyển đổi cú pháp chính và kiểm tra lỗi đã phát hiện |

### Mục tiêu

- Giữ nguyên cấu trúc nghiệp vụ, tên bảng và quan hệ dữ liệu khi có thể.
- Chuyển đổi kiểu dữ liệu và cú pháp đặc thù của SQL Server.
- Bảo toàn primary key, foreign key, `CHECK`, `UNIQUE`, `ON DELETE CASCADE` và trigger.
- Đảm bảo dữ liệu mẫu được nạp theo đúng thứ tự phụ thuộc khóa ngoại.
- Chuẩn bị database để ứng dụng kết nối và thực hiện CRUD.

## 2. Phạm vi chuyển đổi

Quá trình gồm:

1. Sao lưu script SQL Server gốc.
2. Tạo database PostgreSQL.
3. Chuyển đổi schema và kiểu dữ liệu.
4. Chuyển đổi identity column.
5. Chuyển đổi computed column.
6. Sửa identifier bị escape sai.
7. Kiểm tra constraint, foreign key, trigger và function.
8. Sắp xếp thứ tự tạo bảng và insert dữ liệu.
9. Kiểm tra ứng dụng sau khi đổi connection string.

Không thay đổi nghiệp vụ ngoài những phần cần thiết để PostgreSQL thực thi đúng.

## 3. Các khác biệt SQL Server và PostgreSQL

### 3.1. Identity column

SQL Server:

```sql
"Id" INT IDENTITY(1,1) PRIMARY KEY
```

PostgreSQL:

```sql
"Id" INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

`BY DEFAULT` cho phép seed dữ liệu có chỉ định ID khi cần.

### 3.2. Computed column

SQL Server:

```sql
"ThanhTien" AS ("SoLuongNhap" * "DonGiaNhap") PERSISTED
```

PostgreSQL:

```sql
"ThanhTien" NUMERIC(17, 2)
GENERATED ALWAYS AS ("SoLuongNhap" * "DonGiaNhap") STORED
```

Ví dụ đầy đủ:

```sql
CREATE TABLE "CT_PhieuNhap"
(
    "Id" INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "MaPhieuNhap" INT NOT NULL REFERENCES "PhieuNhapSach"("Id") ON DELETE CASCADE,
    "MaSach" INT NOT NULL REFERENCES "Sach"("Id") ON DELETE CASCADE,
    "SoLuongNhap" INT NOT NULL CHECK ("SoLuongNhap" > 0),
    "DonGiaNhap" NUMERIC(15, 2) NOT NULL CHECK ("DonGiaNhap" >= 0),
    "DonGiaBan" NUMERIC(15, 2) NOT NULL CHECK ("DonGiaBan" >= 0),
    "ThanhTien" NUMERIC(17, 2)
        GENERATED ALWAYS AS ("SoLuongNhap" * "DonGiaNhap") STORED,
    CONSTRAINT "CHK_DonGiaNhap_DonGiaBan"
        CHECK ("DonGiaNhap" <= "DonGiaBan")
);
```

`ThanhTien` được tính tự động; khi `INSERT` không truyền giá trị cho cột này.

### 3.3. Identifier và dấu ngoặc kép

Sai:

```sql
d.""Id""
p.""Id""
```

Đúng:

```sql
d."Id"
p."Id"
```

Trong PostgreSQL, `"Id"` là identifier hợp lệ; `""` hoặc `""""` là identifier rỗng hoặc chuỗi quote sai.

### 3.4. Một số ánh xạ kiểu dữ liệu và hàm

| SQL Server | PostgreSQL |
|---|---|
| `NVARCHAR` | `VARCHAR` hoặc `TEXT` |
| `BIT` | `BOOLEAN` |
| `DATETIME` | `TIMESTAMP` |
| `MONEY` | `NUMERIC` |
| `DECIMAL(p,s)` | `NUMERIC(p,s)` |
| `GETDATE()` | `CURRENT_TIMESTAMP` |
| `ISNULL(a,b)` | `COALESCE(a,b)` |
| `TOP n` | `LIMIT n` |
| `GO` | Không dùng trong PostgreSQL |

Chỉ áp dụng ánh xạ phù hợp với đối tượng thực tế trong script.

## 4. Các lỗi đã gặp

### Lỗi 1: Zero-length delimited identifier

```text
ERROR: zero-length delimited identifier at or near """"
```

Nguyên nhân: tên cột bị escape sai, ví dụ `d.""Id""`.

Cách sửa: đổi thành `d."Id"` và rà soát toàn bộ script để không còn `""` hoặc quote dư.

### Lỗi 2: Syntax error at or near AS

```text
ERROR: syntax error at or near "AS"
```

Nguyên nhân: sử dụng computed-column syntax của SQL Server:

```sql
"ThanhTien" AS (...) PERSISTED
```

Cách sửa:

```sql
"ThanhTien" NUMERIC(17, 2)
GENERATED ALWAYS AS (...) STORED
```

### Lỗi 3: Vi phạm khóa ngoại khi insert seed data

Bảng con không được insert trước bảng cha. Thứ tự phải là:

```text
Bảng độc lập/danh mục
    ↓
Sach
    ↓
PhieuNhapSach hoặc DonHang
    ↓
CT_PhieuNhap hoặc CT_DonHang
```

Nếu có bảng kho phụ thuộc vào sách, phải tạo và nạp dữ liệu sau khi bảng `Sach` tồn tại.

## 5. Quy trình migration

### Bước 1 — Sao lưu script gốc

Giữ file SQL Server nguyên trạng:

```text
database/sqlserver/BookStoreDB_SQLServer.sql
```

Không sửa trực tiếp bản gốc.

### Bước 2 — Tạo database PostgreSQL

```sql
CREATE DATABASE "BookStoreDB";
```

Trong DBeaver, chuyển connection sang database `BookStoreDB` trước khi chạy schema.

### Bước 3 — Chuyển đổi schema

Thay các cú pháp đặc thù SQL Server theo bảng tương thích ở trên. Giữ tên bảng/cột nếu ứng dụng đang phụ thuộc vào chúng.

### Bước 4 — Tạo bảng theo phụ thuộc

Tạo bảng cha trước bảng con. Nếu không thể sắp xếp, tạo bảng trước rồi thêm foreign key bằng `ALTER TABLE` sau.

### Bước 5 — Tạo constraint, function và trigger

Sau khi các bảng liên quan tồn tại, tạo foreign key còn thiếu, function và trigger. Kiểm tra phần thân function theo PL/pgSQL thay vì T-SQL.

### Bước 6 — Nạp seed data

Không insert vào generated column:

```sql
INSERT INTO "CT_PhieuNhap"
("MaPhieuNhap", "MaSach", "SoLuongNhap", "DonGiaNhap", "DonGiaBan")
VALUES (1, 1, 10, 50000, 75000);
```

PostgreSQL tự tính `ThanhTien = 500000`.

### Bước 7 — Chạy kiểm tra schema và dữ liệu

Chỉ sau khi schema và seed data thành công mới kiểm tra ứng dụng.

## 6. Các câu lệnh kiểm tra

### Phiên bản

```sql
SELECT version();
```

### Danh sách bảng

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
ORDER BY table_name;
```

### Cột và kiểu dữ liệu

```sql
SELECT table_name, column_name, data_type, is_nullable,
       column_default, is_generated
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position;
```

### Constraint

```sql
SELECT table_name, constraint_name, constraint_type
FROM information_schema.table_constraints
WHERE table_schema = 'public'
ORDER BY table_name, constraint_type;
```

### Trigger

```sql
SELECT trigger_name, event_object_table,
       action_timing, event_manipulation
FROM information_schema.triggers
WHERE trigger_schema = 'public'
ORDER BY event_object_table, trigger_name;
```

### Số lượng dữ liệu

```sql
SELECT COUNT(*) FROM "Sach";
SELECT COUNT(*) FROM "PhieuNhapSach";
SELECT COUNT(*) FROM "CT_PhieuNhap";
SELECT COUNT(*) FROM "DonHang";
SELECT COUNT(*) FROM "CT_DonHang";
```

### Generated column

```sql
SELECT column_name, data_type, is_generated,
       generation_expression
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'CT_PhieuNhap';
```

- Đọc danh sách sách.
- Thêm, sửa và xóa sách.
- Tạo phiếu nhập.
- Tạo đơn hàng.

## 10. Bài học rút ra

1. SQL không hoàn toàn portable giữa các hệ quản trị.
2. Identity, computed column, kiểu dữ liệu và hàm hệ thống cần được rà soát riêng.
3. Dấu quote trong SQL không giống escaping trong Java, C#, Python hoặc Markdown.
4. Thứ tự tạo bảng và nạp dữ liệu phải tuân thủ dependency graph.
5. Chạy script thành công không đồng nghĩa ứng dụng đã đúng.
6. Migration nên có script có thể tái lập và tài liệu đi kèm.

## 11. Kết quả cuối cùng

BookStoreDB được chuyển đổi theo hướng giữ nguyên cấu trúc nghiệp vụ và thay thế các phần đặc thù SQL Server bằng cú pháp PostgreSQL tương ứng. Các lỗi đã xác định gồm quote identifier sai và computed column dùng `PERSISTED`; hai lỗi này được xử lý bằng identifier PostgreSQL hợp lệ và `GENERATED ALWAYS AS (...) STORED`.
